# plan-trusted-device-connections 设计摘要

## Context

现有 ClientPlatform 只有本机资料、权限和发现，NearbyDevice 仅包含 id/name/platform；发现实现不建立可信协议。公共媒体 API 也没有远端身份或信令接口。动机见 proposal.md。

本文件是既有设计迁移，lifecycle/delivery 均为 planned，能力尚未实现；此次只整理规格，不表示已授权实施，也不恢复已停止的产品开发。规格版本 0.1.0、产品基线 0.1.0、release-target 0.1.0。具体实现需另行进入 apply，并先解决下文的设计门槛。

### 已确认的公开产品约束

用户已确认设备间连接授权独立于邀请资格；直连优先，默认提供官方 STUN/TURN，已激活设备的局域网使用不依赖公网。发现、信令与中继是不同职责。

## Goals / Non-Goals

将可信身份、配对状态、目录展示和连接尝试拆开，公开连接协议可供客户端与 SDK 共用。非目标：本次不恢复跨网产品实现、不部署服务、不把某个发现 UUID 当作长期身份，不创建独立云目录服务。

## Decisions

以下划分保留用户已确定的边界；标为候选的内容仍是未实现的技术建议，不提升为已确认产品需求。

1. 职责分层：保留现有发现作为不可信入口，由未来身份验证流程产生配对记录；目录组合发现与可信资料。单一“在线即可信”状态会丢失授权信息，因此不采用。

2. 候选连接方案：本地可达信令先行，按需补充官方或内网信令；WSS、Trickle ICE、异步获取短期辅助凭据是既有技术建议，尚未确定消息格式和 SDK 接口。具体库、超时和服务数量不构成产品需求。

3. 辅助配置选择：自定义内网配置作为显式模式；官方故障不得阻断本地连接。TURN 只转发数据，无法补足被阻断的信令。候选实现以连接尝试代次隔离旧响应，并按实际候选对诊断路径。

4. 跨仓协作：公开定义身份/会话材料与错误，SDK 执行方核验必要材料；在接口形成后更新契约及兼容测试，不把 UI 是否已配对的布尔值当作证明。

## Risks / Trade-offs

- 发现记录可伪造 → 仅作为候选入口，可信身份独立验证。
- 把设计中的固定超时当作时延承诺 → 超时策略需实验和评审，规格不固定秒数。
- 内网不可互通或信令被阻断 → 分层报告可达性，不承诺安装 TURN 后必然连接。

## Migration Plan

在实现授权后先确认身份/信令契约，建立协议测试，再添加客户端状态与 SDK 适配，最后双机验证本地断公网和辅助路径。保留发现基线；新流程失败回到明确未连接状态。回退旧客户端时不把未知版本可信记录静默解释为有效。

## Decisions Required Before Implementation

配对确认形式、身份算法与平台存储、消息版本、重放防护字段、信令可达性补充方式以及凭据响应取消语义必须在实现前解决。目标 0.1.0 不等于这些方案已经通过评审。

当前计划文件已整理齐全，但这些门槛解决前不应声称具备可直接执行的最终接口设计。任何新增产品范围先更新版本计划，具体任务见 tasks.md，全部保持未完成。
