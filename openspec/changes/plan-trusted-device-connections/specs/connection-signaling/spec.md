# 连接信令与路径选择

## Purpose

将既有设计中的连接信令与路径选择整理为可审阅的未来行为契约。当前能力尚未实现，本次仅迁移规格；规格版本独立维护，目标版本只说明规划归属，不代表已经授权开发、完成验收或承诺发布日期。

## ADDED Requirements

### Requirement: 身份绑定的信令

会话信令 MUST 验证消息属于当前已验证对端和连接尝试，拒绝错误身份、旧尝试和重复失效的消息；中继或信令服务转发不代替对端验证。

#### Scenario: 旧尝试响应

- **WHEN** 用户重试连接后，旧会话的协商消息才到达
- **THEN** 消息不能改变当前连接或恢复已取消会话。

### Requirement: 直连与离线边界

连接流程 MUST 优先可成功建立的直接路径，不等待公网配置、凭据接口或官方服务后才尝试可达的本地连接；已激活用户本地功能不依赖周期联网检查。

#### Scenario: 官方服务不可达而局域网可达

- **WHEN** 双方已激活并可本地互通，官方辅助请求失败
- **THEN** 继续建立本地直连，不取消本地资格或显示必须部署中继。

### Requirement: 官方与自定义内网配置

客户端 MUST 提供官方默认辅助和用户自定义内网辅助的明确选择；启用自定义配置后使用所选配置，不静默恢复公网转发，用户可主动恢复默认。

#### Scenario: 内网配置失效

- **WHEN** 用户选择的内网服务不可达
- **THEN** 报告所选配置失败，不偷偷改用官方公网中继。

### Requirement: 分层诊断与引导

客户端 MUST 区分发现、信令、连接路径和媒体首帧失败；仅当直连及可用辅助路径未能建立连接时给出相关配置引导，不把 TURN 当作发现或信令的替代。

#### Scenario: 信令被阻断

- **WHEN** 双方已发现但不存在可达信令路径
- **THEN** 报告信令不可达并给出对应处理信息，不宣称只安装 TURN 即可连通。

#### Scenario: 所有已选路径失败

- **WHEN** 直连失败且官方辅助不可用
- **THEN** 提示配置已有内网 STUN/TURN 或查看内网部署指导，说明仍需要双方可达的信令和网络路径。

### Requirement: 取消与实际路径状态

连接尝试 MUST 可取消；成功状态及直连/中继标签依据实际已建立会话和所选路径，不根据配置列表推断。

#### Scenario: 取消凭据请求

- **WHEN** 用户取消时辅助凭据尚未返回
- **THEN** 晚到凭据不得启动或重建连接。

#### Scenario: 配置中包含 TURN

- **WHEN** 会话实际使用直接路径
- **THEN** 展示直连，不声称流量已经走中继。

## Verification

- 分别验证同一局域网断公网、官方辅助不可用、自定义内网模式、信令被阻断、实际直连和实际中继。
- 记录真实选中路径与对端数据/媒体结果，使用配置项或候选存在不足以通过验收。

所有场景均为待验收项；现有单元测试、局部平台构建与媒体实验不构成本能力已经交付的证据。
