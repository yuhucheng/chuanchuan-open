# 可信设备配对

## Purpose

将既有设计中的可信设备配对整理为可审阅的未来行为契约。当前能力尚未实现，本次仅迁移规格；规格版本独立维护，目标版本只说明规划归属，不代表已经授权开发、完成验收或承诺发布日期。

## ADDED Requirements

### Requirement: 身份与发现分离

配对流程 MUST 验证对端持有的设备身份材料并将用户确认绑定到该对端；局域网名称、地址、发现 UUID 或邀请码资格本身不得建立设备信任。

#### Scenario: 冒用同名设备

- **WHEN** 未受信任的设备使用已信任设备的名称或发现 UUID 请求连接
- **THEN** 客户端仍要求身份验证，不复用原设备的授权。

### Requirement: 同意与取消

客户端 MUST 在配对完成前取得本次所需的用户确认；拒绝、取消或超时不保存可用信任，晚到响应不能把取消的请求变成成功。

#### Scenario: 取消后晚到成功

- **WHEN** 用户取消配对后收到对端确认
- **THEN** 本次请求保持取消，不能建立可信设备条目或会话。

### Requirement: 移除本地信任

客户端 MUST 允许用户在局域网离线时移除本机保存的对端信任，并终止依赖该信任的当前会话授权。

#### Scenario: 离线撤销信任

- **WHEN** 公网不可用，用户移除已配对设备
- **THEN** 本地立即停止接受该设备的既有信任，新会话重新验证和授权。

### Requirement: 信任与操作授权分离

设备已配对 MUST 不自动授予录屏、观看、远控输入或文件接收权限；每项能力仍满足其自身的会话同意和系统权限。

#### Scenario: 已配对设备越权控制

- **WHEN** 仅获配对信任的设备提交输入操作
- **THEN** 执行侧拒绝输入，并保持观看/控制授权状态的真实区别。

## Verification

- 使用两个独立身份的真实设备验证正常配对、错配身份、同名冒用、取消、超时与本地移除信任。
- 协议格式、密钥存储和配对确认机制需在实现前评审并形成配套契约测试。

所有场景均为待验收项；现有单元测试、局部平台构建与媒体实验不构成本能力已经交付的证据。
