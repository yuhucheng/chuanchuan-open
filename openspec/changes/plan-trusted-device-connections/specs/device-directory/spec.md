# 客户端设备目录

## Purpose

将既有设计中的客户端设备目录整理为可审阅的未来行为契约。当前能力尚未实现，本次仅迁移规格；规格版本独立维护，目标版本只说明规划归属，不代表已经授权开发、完成验收或承诺发布日期。

## ADDED Requirements

### Requirement: 目录与信任状态

设备目录 MUST 区分正在发现的设备、已配对设备和本次已连接设备；展示名称相同或网络可见不代表身份相同、已授权或已连接。

#### Scenario: 发现同名陌生设备

- **WHEN** 目录已有可信设备，局域网又出现同名未知身份
- **THEN** 展示为尚未验证的独立设备，不覆盖可信身份。

### Requirement: 实时可达性

目录 MUST 按实际发现和连接反馈更新可达状态；发现记录消失不伪造新的连接，也不把历史在线状态当作当前可达证据。

#### Scenario: 设备离线

- **WHEN** 发现记录过期或连接检查失败
- **THEN** 界面标明不可达或待重试，保留可信资料时明确它只是已保存的资料。

### Requirement: 能力来自当前对端

目录 MUST 根据经过身份绑定的当前能力协商展示观看、控制、发送文件和接收文件操作；未知、撤回或不支持的能力不可显示为已可用。

#### Scenario: 能力撤回

- **WHEN** 已连接设备撤回接收文件能力
- **THEN** 界面停止允许新的文件发送并解释能力变化，既有操作按对应会话规则结束。

## Verification

- 在真实双机发现/连接中对照目录、身份和能力状态；覆盖同名设备、离线、重新连接和能力变化。
- 本能力是客户端资料组织设计，不承诺独立云目录服务或新的在线依赖。

所有场景均为待验收项；现有单元测试、局部平台构建与媒体实验不构成本能力已经交付的证据。
