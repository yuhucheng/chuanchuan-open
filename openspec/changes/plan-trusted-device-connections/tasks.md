## 1. 设计门槛

- [ ] 1.1 确认配对校验方式、身份材料与存储、信令版本及取消语义，将结果写回 design.md 与对应差量规格；以评审记录和 `npm run spec:validate` 通过为完成证据。
- [ ] 1.2 确定并记录 SDK 消费身份/会话材料的公共契约及兼容策略；以客户端和 SDK 维护方可执行的契约样例、错误样例为完成证据。

## 2. 公开客户端与契约实现

- [ ] 2.1 在公开设备模块实现配对拒绝、取消、超时及本地移除信任；添加身份冒用和晚到响应测试，并运行 `flutter test --no-pub` 验证。
- [ ] 2.2 实现区分发现、信任、可达性和能力的目录状态；添加同名设备、离线和能力撤回测试，并验证 UI 不显示越权操作。
- [ ] 2.3 实现已评审的可取消信令与官方/自定义内网配置选择；用协议测试验证旧代次消息隔离、官方失败不阻塞本地、自定义配置不静默回公网。
