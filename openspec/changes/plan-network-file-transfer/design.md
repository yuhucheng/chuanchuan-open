# plan-network-file-transfer 设计摘要

## Context

TransferQueue 的 ready 是本地 SHA-256 与最终文件检查通过，令牌在移除时释放。当前没有远端请求、接收文件句柄、网络背压或接收确认。动机见 proposal.md。

本文件是既有设计迁移，lifecycle/delivery 均为 planned，能力尚未实现；此次只整理规格，不表示已授权实施，也不恢复已停止的产品开发。规格版本 0.1.0、产品基线 0.1.0、release-target unassigned。具体实现需另行进入 apply，并先解决下文的设计门槛。

### 已确认的公开产品约束

文件发送和接收是用户已确认的跨设备目标；文件传输模块开源，文件访问和接收授权独立于邀请和设备配对。网络文件收发尚未排期。

## Goals / Non-Goals

在既有选择授权和准备摘要上增加可信双端收发协议，确保传输状态可核对。非目标：本次不实现网络收发，不新增目录同步或无 SDK 产品入口。

## Decisions

以下划分保留用户已确定的边界；标为候选的内容仍是未实现的技术建议，不提升为已确认产品需求。

1. 将准备、传输和接收确认分开，发送前重新校验内容。把现有 ready 当作已发送会错误报告成功，因此不采用。

2. 候选协议描述文件元数据、内容标识、分块、取消与接收确认，接收侧仅写入用户授权位置。临时文件加验证后提交是候选实现；命名、覆盖和原子提交策略需按平台确定。

3. 有界缓冲及接收背压避免一次加载大文件；通道与协议由公开通用连接层承担，SDK 媒体接口不承载文件读写授权。具体传输块与窗口大小仍待测试。

4. 恢复是新的受约束操作，先核验对端、资格、接收同意及内容一致性，再决定能否继续。自动重试消耗未知状态或沿用旧权限会扩大授权，故不默认采用。

## Risks / Trade-offs

- 恶意文件名越界 → 接收端限制到授权目录并验证名称。
- 源文件变化或损坏 → 发送前与接收完成分别检查。
- 磁盘满、断线或取消留下不完整文件 → 清楚标记未完成，清理策略在平台设计中确定。

## Migration Plan

release-target 为 unassigned；实施前先确定版本计划与协议、接收位置和冲突策略。再用现有队列接入发送、补接收存储、双端状态和取消，最后验证完整性与恢复。协议版本不兼容时拒绝传输，不能把本地准备显示为兼容降级成功。

## Decisions Required Before Implementation

是否支持目录、冲突处理交互、接收持久化、恢复粒度和并发额度为设计门槛；不把既有讨论中的具体默认值当作用户决定。

当前计划文件已整理齐全，但这些门槛解决前不应声称具备可直接执行的最终接口设计。任何新增产品范围先更新版本计划，具体任务见 tasks.md，全部保持未完成。
