# 网络文件收发

## Purpose

将既有设计中的网络文件收发整理为可审阅的未来行为契约。当前能力尚未实现，本次仅迁移规格；规格版本独立维护，目标版本只说明规划归属，不代表已经授权开发、完成验收或承诺发布日期。

## ADDED Requirements

### Requirement: 双方授权和可信对端

文件发送 MUST 使用已验证的对端会话和发送者选择的文件；接收方独立同意接收并授予目标存储访问，已配对或已激活不能代替接收授权。

#### Scenario: 对端拒收

- **WHEN** 接收者拒绝文件请求
- **THEN** 发送端显示拒绝，不发送内容，不在接收侧创建完成文件。

### Requirement: 发送前内容确认

发送方 MUST 在正式发送前重新确认所选文件与准备摘要一致；已变化或不再可读的文件应失败并要求重新选择或准备。

#### Scenario: 准备后修改文件

- **WHEN** 队列已 ready，但开始发送时检测到内容变化
- **THEN** 不沿用旧摘要发送，显示文件变化失败。

### Requirement: 接收完整性和边界

接收方 MUST 限制写入到用户授权位置，检查传输长度与完整性；未经用户确认不得覆盖既有内容，未完整验证的数据不得标为接收完成。

#### Scenario: 文件名包含越界路径

- **WHEN** 对端发送带父目录或绝对路径语义的文件元数据
- **THEN** 拒绝或安全处理为授权目录内名称，不能写入授权范围外。

#### Scenario: 内容校验失败

- **WHEN** 接收内容与声明大小或摘要不符
- **THEN** 标记失败，保留明确的未完成状态，不发布为完整文件。

### Requirement: 进度与背压

双端状态 MUST 区分准备、等待同意、传输中、已接收、取消和失败；传输缓冲必须有界，发送完成不得早于接收方完整验证确认。

#### Scenario: 网络暂时变慢

- **WHEN** 对端消费速度低于发送速度
- **THEN** 限制发送与缓冲增长，进度依据实际传输和确认，不显示虚假完成。

### Requirement: 取消与恢复授权

传输 MUST 支持双端取消并停止后续内容读写；断线或失败后的恢复必须重新确认身份、授权和内容一致性，不能把旧连接授权用于新对端。

#### Scenario: 传输中取消

- **WHEN** 任意一端取消当前传输
- **THEN** 双方终止该传输的后续内容操作并显示取消，晚到数据不变为完成。

#### Scenario: 恢复时源内容改变

- **WHEN** 失败后准备恢复，但文件内容已变化
- **THEN** 拒绝按旧偏移继续，要求重新准备并确认传输。

## Verification

- 后续真实双端验证大于单个传输分块、空文件、拒收、越界元数据、校验损坏、磁盘/权限失败、取消、断线和恢复。
- 确认两端摘要与接收确认一致；当前本地准备和摘要测试不代表任何网络内容送达。
- release-target 为 unassigned，开始实现前须先确定排期及具体传输协议。

所有场景均为待验收项；现有单元测试、局部平台构建与媒体实验不构成本能力已经交付的证据。
