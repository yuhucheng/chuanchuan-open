# plan-network-file-transfer 任务清单

以下均为尚未执行的未来任务。本次既有设计迁移只整理文档，不表示已授权产品开发；规格版本 0.1.0，产品基线 0.1.0，release-target unassigned。先完成设计门槛，再依据新的实施授权进入 apply；不得自行建分支/worktree或推定未排期能力的发布版本。

## 1. 范围与协议门槛

- [ ] 1.1 在实现前确定网络文件收发目标版本、接收位置/冲突策略、目录范围与恢复粒度；更新版本计划和 design.md，以评审记录及 `npm run spec:validate` 为完成证据。
- [ ] 1.2 确定文件元数据、分块、确认、取消和恢复的版本化公开协议；交付正常及损坏、拒收、越权样例，验证与连接层身份和授权规则一致。

## 2. 发送和接收

- [ ] 2.1 在发送前重新核验已有本地令牌与摘要，实现有界发送；添加源文件变化和慢接收方背压测试，运行 `flutter test --no-pub`。
- [ ] 2.2 实现用户同意后的平台接收存储适配与完整性验证；添加越界路径、覆盖未授权、磁盘满和摘要不符测试，验证未完整文件不被标为完成。
- [ ] 2.3 实现双端进度、确认、取消和按已评审规则恢复；以断线、晚到分块、取消后无后续写入及内容变化拒绝恢复的测试为完成证据。

## 3. 双端验收

- [ ] 3.1 运行公开客户端静态检查与测试，在目标 Windows/macOS 构建中验收真实发送/接收、空文件、大文件、拒收和中途取消，核对两端摘要与接收确认。
- [ ] 3.2 断开公网后验证可互通局域网收发，并记录断线恢复及文件授权撤回结果；未通过平台保留待办，不将本地 ready 状态计为送达。
