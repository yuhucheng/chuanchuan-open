# 客户端邀请激活

## Purpose

将既有设计中的客户端邀请激活整理为可审阅的未来行为契约。当前能力尚未实现，本次仅迁移规格；规格版本独立维护，目标版本只说明规划归属，不代表已经授权开发、完成验收或承诺发布日期。

## ADDED Requirements

### Requirement: 首次邀请激活

官方客户端首次取得产品使用资格 MUST 联网完成邀请激活；界面区分未激活、处理中、失败和已激活，不能由用户输入或本地布尔状态直接宣告资格有效。

#### Scenario: 邀请码兑换失败

- **WHEN** 官方服务拒绝兑换或无法完成激活
- **THEN** 显示可理解的失败状态，不保存伪造的已激活状态；允许按错误类型修正或重试。

### Requirement: 激活后离线可用

已激活用户的屏幕共享、远控和文件传送 MUST 在网络实际互通的局域网中离线可用；官方服务、DNS 或辅助凭据接口暂时不可用不能取消本地资格或要求周期联网才能继续使用。

#### Scenario: 激活后断开公网

- **WHEN** 已激活设备仍可在局域网互通
- **THEN** 本地资格验证和已实现的核心功能继续可用，仍分别执行设备与会话授权。

### Requirement: 可信材料和职责

客户端 MUST 将可验证的资格材料交给相关可信执行方检查，公开 UI 状态不能替代凭证验证；邀请资格、设备配对、远控同意和文件访问授权各自独立。

#### Scenario: 界面状态被更改

- **WHEN** 界面宣称已激活但资格材料验证失败
- **THEN** 执行方拒绝依赖资格的官方能力，不把 UI 布尔值当作授权。

#### Scenario: 已激活但未获控制同意

- **WHEN** 已激活用户向另一设备发送控制请求
- **THEN** 仍需独立控制授权，不能因产品资格直接注入输入。

### Requirement: 取消和状态保护

客户端 MUST 允许取消当前激活交互，并隔离晚到请求结果；失败或取消不得破坏已有有效资格。取消后的服务端兑换结果未知时，应提供可核对的状态而非保证已撤销兑换。

#### Scenario: 激活请求取消后返回

- **WHEN** 用户取消交互后网络响应到达
- **THEN** 不重新打开已取消流程或误报资格；后续状态核对遵循明确的兑换协议，不静默重复消费邀请码。

## Verification

- 后续验证新设备兑换、无效邀请、断网、取消后晚到响应、凭证损坏及已激活设备彻底断公网。
- 需要跨 SDK/服务契约测试证明公开 UI 不能授予执行权限。
- 当前未实现激活；绑定、迁移、重装和服务端撤销的离线语义尚未设计完成。

所有场景均为待验收项；现有单元测试、局部平台构建与媒体实验不构成本能力已经交付的证据。
