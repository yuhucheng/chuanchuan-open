# plan-client-activation 设计摘要

## Context

当前 UI 明示邀请码激活尚未接入；设备发现 ID 不是激活凭证，公共媒体 API 也没有资格验证材料。动机见 proposal.md。

本文件是既有设计迁移，lifecycle/delivery 均为 planned，能力尚未实现；此次只整理规格，不表示已授权实施，也不恢复已停止的产品开发。规格版本 0.1.0、产品基线 0.1.0、release-target unassigned。具体实现需另行进入 apply，并先解决下文的设计门槛。

### 已确认的公开产品约束

用户已确认官方软件免费、无订阅，收入来自捐赠；邀请准入以普通用户为主要邀请来源，管理员少量发放；首次联网激活，之后核心功能在可互通局域网离线可用。

## Goals / Non-Goals

把客户端资格展示、资格材料、平台保存和 SDK/服务验证职责分开。非目标：本次不实现邀请服务，不确定用户/设备绑定、邀请额度或新的付费条件。

## Decisions

以下划分保留用户已确定的边界；标为候选的内容仍是未实现的技术建议，不提升为已确认产品需求。

1. 候选方案由在线服务兑换邀请并签发可本地验证的资格材料，客户端只保管使用材料，不拥有签发权。单纯持久化 isActivated 不能为执行方提供信任，故不采用。凭证格式和验签接口仍待评审。

2. 激活服务联网要求只作用于首次准入及相应管理，不形成已激活用户核心局域网功能的周期在线门槛。在线辅助连接令牌失效与本地激活资格分开。

3. 用户界面、SDK 执行检查、设备配对和每次操作权限分别设置状态。产品资格不授予访问任意设备的权利；取消交互也不等于服务端已经撤销成功兑换。

4. 完全离线的设备不能立即得知新的服务端资格撤销。迁移、换机和重新联网的处理需设计并符合离线承诺，本次不指定到期策略。

## Risks / Trade-offs

- 取消后重复兑换 → 先设计请求标识和结果核对，保护已有有效资格。
- 本地凭证被伪造或 UI 绕过 → 执行方验证可验证材料，按错误分类失败。
- 周期刷新不慎成为本地硬依赖 → 断公网验证作为必需验收。

## Migration Plan

release-target 为 unassigned；先设计用户设备关系、邀请协议、资格材料和撤销规则，再按公开契约实现 UI/存储/SDK 集成。资格存储迁移须保留可恢复的旧材料，失败不覆盖有效状态；尚未激活的开发状态不能伪装为生产资格。

## Decisions Required Before Implementation

邀请是否单次、额度与有效期、设备绑定和迁移、重装、服务端撤销及时间相关策略必须另行确定。捐赠和资格规则的细节未被自动推定；不引入“每人 3 个邀请”等未确认值。

当前计划文件已整理齐全，但这些门槛解决前不应声称具备可直接执行的最终接口设计。任何新增产品范围先更新版本计划，具体任务见 tasks.md，全部保持未完成。
