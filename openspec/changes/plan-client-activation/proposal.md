# plan-client-activation

## Why

邀请准入与首次联网激活是既有产品约束，但客户端当前尚未接入激活。迁移客户端侧需求，确保激活后的局域网离线使用不被官方服务故障或周期联网要求取消。

本提案为既有设计迁移，lifecycle 为 planned、delivery 为 planned；尚未实现，任务清单不表示已授权开发，也不恢复此前停止的产品功能实施。规格版本为 0.1.0，产品基线为 0.1.0，release-target 为 unassigned（尚未排期）。

## What Changes

- 规划邀请码输入与激活状态展示，以及失败和取消交互。
- 将产品资格、设备配对、会话同意与文件权限分别处理。
- 定义可在本地验证资格的材料及与 SDK 的可信接口目标，保留迁移撤销的未决问题。
- 本次仅形成规划文档；未决技术建议和实现授权需在开始 apply 前按版本计划处理。

## Capabilities

### New Capabilities

- `client-activation`: 首次邀请激活、本地资格状态和离线使用边界。

### Modified Capabilities

无。当前基线保持原状；待接口方案明确后再以独立变更描述确有影响的 API 要求。

## Impact

未来涉及公开客户端激活页面、平台凭证存储适配和 SDK 凭证验证契约；邀请生成、兑换、凭证签发与后台属于官方服务。本仓不得持有签发私钥，也不能通过 UI 布尔值授予 SDK 权限。

未决范围：用户与设备关系、邀请额度/有效期/撤销、凭证格式、设备绑定、换机和重装流程、离线撤销规则均待设计；不预设初始 3 个邀请或单次码为已确认要求。
