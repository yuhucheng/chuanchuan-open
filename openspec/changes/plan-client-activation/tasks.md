# plan-client-activation 任务清单

以下均为尚未执行的未来任务。本次既有设计迁移只整理文档，不表示已授权产品开发；规格版本 0.1.0，产品基线 0.1.0，release-target unassigned。先完成设计门槛，再依据新的实施授权进入 apply；不得自行建分支/worktree或推定未排期能力的发布版本。

## 1. 资格设计门槛

- [ ] 1.1 确定目标版本、用户设备关系、邀请规则、凭证绑定/迁移/撤销和离线语义；更新版本计划及 design.md，以明确决策和 `npm run spec:validate` 为完成证据。
- [ ] 1.2 与 SDK/服务维护方确定兑换请求标识、取消后状态核对、资格材料和错误契约；交付无效凭证、未知兑换结果与有效离线资格的契约测试样例。

## 2. 客户端激活流程

- [ ] 2.1 实现邀请输入、处理中、失败与取消状态，保护已有有效资格；用重复请求、取消晚到、网络失败和无效邀请测试验证，再运行 `flutter test --no-pub`。
- [ ] 2.2 实现平台资格材料保存与恢复，并接入可信执行方验证接口；通过损坏材料和伪造 UI 布尔值测试证明不能授予官方执行权限。
- [ ] 2.3 保持激活、配对、观看、控制和文件权限状态独立；通过已激活但未配对/未同意的越权请求测试验证。

## 3. 离线与迁移验收

- [ ] 3.1 运行 `flutter analyze --no-pub`、`flutter test --no-pub` 与目标平台构建，在真实设备完成首次联网激活后断开公网，验证本地资格与已实现核心功能。
- [ ] 3.2 按已批准迁移/撤销策略验证重装、换机或重新联网场景，记录失败不破坏有效资格、官方辅助故障不取消本地资格的结果；无结论项不能勾选通过。
