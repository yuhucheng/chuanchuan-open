# 本机预览启动取消与停止所有权

2026-09-30，三仓为 `release/v0.1.0`；公开基于 `b58d878`，私有 SDK `518a756`，公共媒体 API 0.8.0，Flutter 3.47.2 / Dart 3.13.2。修改在公开预览控制器及两个回归文件，未改 SDK、公共 API、Windows 原生诊断或双机入口。

## 问题与处理

原控制器先等待 `_pending`，再请求 `engine.stop()`。原生启动需要停止请求才能结算时，客户端无法触发取消；现有回归只在测试手动完成启动后核验释放，没有覆盖这个依赖方向。另在 `stopping` 状态通知里同步重入 `stop()` 时，旧代码尚未保存清理 Future，会创建第二条清理链路。

先运行增强回归，三个断言失败：挂起启动期间引擎 stop 次数为 0、真实 SDK Dart 适配器的原生 stop 通道调用为 0，以及重入调用没有取得同一 Future。

修复先登记唯一停止 Future，再发状态通知；SDK 停止立即发起，错误处理器在等待启动前安装。停止仍等待启动和实际清理结算，不提前释放画面预算。首轮清理成功后，对迟到启动再确认释放，兼容不能取消原生分配的旧引擎；首轮清理失败不自动重试，保留 `cleanupFailed` 与预算，后续明确停止可重试。旧首帧/结束事件仍不能复活画面或结束下一次预览。

这不会赋予每个引擎新的取消保证，也没有将挂起工作伪装成清理完成。SDK 或系统调用无法及时结束时，停止仍等待其实际终态；完整退出的有界清理及错误提示沿用现有进程生命周期逻辑。
