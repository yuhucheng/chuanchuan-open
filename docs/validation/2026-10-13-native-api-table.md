# Native function-table discovery

SDK ABI design now has an executable optional bootstrap for the existing 57 C
calls. `shm_draft_get_api` negotiates draft boundary revision, minimum table version
and caller storage before creating a core. Table version 1 and boundary revision 2
are separate; stable ABI major/minor support remains pending. Old candidates may
lack this optional symbol and must report discovery unavailable explicitly.

The 24-byte descriptor and 480-byte v1 function table have fixed pointer layout.
Short or incompatible calls copy no function pointers. Successful calls return
actual written size and zero a larger caller tail. Function presence conveys no
media capability or authenticated authorization. Existing DTOs and lifecycle/
provider/lease rules are unchanged; the normal Dart factory retains its old calls.

Validation on macOS arm64:

- C11/C++17 declarations, import/export variants and table offsets passed for
  Mac arm64/x86_64 and Windows x64/ARM64 compiler targets. These are layout checks,
  not Windows execution or linker/dependency acceptance.
- Real universal standalone libraries exposed the bootstrap and passed independent
  C callers on arm64 and x86_64 (Rosetta). The tests cover capacity 0 through
  16 KiB, null/over-limit buffers, mismatch gating, canaries, all 57 typed slots,
  larger zeroed tails, unchanged core sequence on discovery, capabilities and
  actual create/seal/close/release. Existing authority, source/frame and controlled
  remote ownership/send/protocol callers also passed on both slices.
- The native arm64 table probe passed AddressSanitizer/UndefinedBehaviorSanitizer.
- Ordinary Mac Debug build passed. Read-only query of its actual SDK framework
  returned BUFFER_TOO_SMALL with descriptor-only output for 24 bytes, OK with all
  57 entries for a 544-byte caller, and INCOMPATIBLE_ABI with zero pointers for a
  wrong boundary revision. The app was not launched and no core was created in
  this framework query.
- The three private C header snapshots match canonical public bytes. The Mac
  candidate exporter now shares that same three-name header list; a fresh full
  client candidate has not been generated by this check. Historical artifacts
  remain unchanged.

No OS source enumeration/capture, GUI, actual Windows/Intel hardware, two-device
or online acceptance is added. Standalone ownership library capabilities remain
zero; its function table does not turn it into a product media implementation.
Stable ABI, full platform migration, public authenticated provider samples and
formal package/trust/install acceptance remain pending.
