# 首次会合帧应答丢失后的重试

六码跨网会合的 `/v1/meet/send` 在服务已接收帧但 HTTPS 应答丢失时，原客户端立即关闭 wire，握手或活动会话因此失败。现在客户端仅对 `timeout` / `unreachable` 用**相同序号和相同帧**再发送一次；取消、明确拒绝和其他错误不重试。私有服务对同一成员最后接受的同序号同内容请求只重新确认，不重复入队；修改帧或旧序号仍拒绝。

同一问题也会发生在握手后的 `/v1/meet/activate`：服务已激活唯一尝试，却未能把确认传回接入端。客户端现在以完全相同的激活请求重试一次；服务已有的幂等分支返回原会话，不延长本次 grant 或路由期限。取消后不重试。

验证：连接包 `dart test` 94/94，其中 `meeting_service_client_test.dart` 12/12；发送用例让第一次发送已经入队但响应超时，确认客户端重试后 wire 仍可用、服务队列只有一份；完整 v2 PAKE/grant 用例让激活已生效但确认丢失，确认两次请求字节字段一致且最终连接仍成立。`dart analyze` 两个修改文件无问题。使用 Flutter 固定的 Dart 3.13.2；未运行用户要求跳过的 Mac 采集 fixture。

此项改善既有首次会合链路的暂时丢包恢复，不等于所选服务已上线、陌生异网双机连接或实际媒体成功。
