# 设备名称与发现卡片切换修复（2026-09-30）

## 问题与修复

桌面原生设备资料使用通用默认名「我的 Mac」「我的 Windows」，远端直接显示该名称，无法说明实际电脑。现在首次读取改为系统电脑名称：macOS 使用 `SCDynamicStoreCopyComputerName`，Windows 使用 `GetComputerNameExW(ComputerNamePhysicalDnsHostname)`；经过既有名称校验，读取失败或名称非法时分别使用 `Mac`、`Windows`。

旧通用默认名迁移一次，保留发现 UUID 和其他有效自定义名称。`deviceNameDefaultVersion=2` 防止迁移完成后用户主动保存的同名文本在重启时再次被覆盖。默认名称初始化后仍是应用保存的名称，不实时跟随系统重命名；用户可在设置的设备名称中修改并保存。

发现记录的公钥与端点随允许连接变化而撤下/出现。设备目录原本以公钥优先、无公钥时以发现 UUID 为展示身份，设备场又保留离线节点，因而同一个 UUID 可留下两张未认证卡片。目录现在保留仅供显示关联的 `discoveryId`。设备场只替换同一 UUID、同一平台、在当前快照已不存在的唯一未认证旧卡片，且要求新旧至少一方无公钥；替换保留位置及焦点。已验证历史和两个不同公钥不合并，名称及地址不用于归并或授予信任。

该路径与用户提供的「一台 Windows、离线与未认证发现各一张」截图相符。没有本轮原始发现 TXT 抓取或真实 Windows/Mac 双机操作证据，不能据此断言截图只可能由这一原因产生。

## 验证

在公开仓 `release/v0.1.0`、Flutter 3.47.2 / Dart 3.13.2 下执行：

- `flutter test --no-pub`：322 通过、1 跳过，无失败。新增组件用例覆盖带公钥 → 无公钥 → 带公钥、位置与焦点、点击读取当前公钥、不同公钥保留，以及已验证身份重新出现时清除无公钥的未认证旧卡。
- `flutter analyze --no-pub` 和最终改动 Dart 文件静态分析：无问题。
- `swift test`：11/11，通过系统名校验、旧默认名迁移、发现 UUID 保持、自定义名称保存与重启保持。
- `flutter build macos --debug --no-pub`：普通产品构建成功。
- `git diff --check`：通过。

Windows 注册表原生测试已更新，覆盖实际系统名称、旧默认值迁移、自定义名称保留及原有错误处理，但本机没有执行 Windows 构建/原生测试或 Windows 实机验收。Mac 普通构建及组件模拟不替代真实双机的开关与发现验收。

要看到两端系统名，两端需运行包含本修复的新构建；旧 Windows 客户端仍广播它保存的名称，也可在其设置中先手动改名。
