# macOS 菜单栏入口失败后的退出清理

原生 `MainFlutterWindow` 曾以菜单栏入口是否成功作为退出时请求 Dart 清理的条件。若入口初始化失败，应用仍可从主窗口建立连接或启动预览，但关闭窗口或 Cmd+Q 会直接结束进程，跳过授权撤销、远端媒体、文件令牌与发现服务的统一清理。

现在原生侧独立记录 Dart 生命周期处理器已注册；之后即使菜单栏入口失败，也通过 `requestExit` 等待同一清理事务。处理器尚未注册的启动早期仍可直接退出。清理失败时保持主窗口可达并允许重试。

验证：`flutter test --no-pub` 338/338、`flutter analyze --no-pub` 无问题，普通 `lib/main.dart` macOS Debug 应用构建通过。新增 Dart 回归确认菜单栏初始化报错后统一退出仍执行媒体、连接、预览和发现清理。未在真实 AppKit 环境故意制造菜单栏图标失败，也未执行完整后台/录屏生命周期矩阵；这些平台验收仍待完成。
