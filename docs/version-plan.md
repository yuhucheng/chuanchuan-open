# 版本计划

## v0.1.0 — 开发中

- 产品基线：`VERSION = 0.1.0`，客户端与内部 SDK 当前为 `0.1.0-dev.1`，尚未发布稳定版；公共媒体 API 当前为 `0.1.0`。
- 开发主线：两个仓库均为 `main`。无获批的例外分支，无承诺发布日期。
- 本轮范围：合并现有 Mac 提交；将 macOS 原生预览放入闭源 SDK，保留唯一开源客户端与必需 SDK 依赖；统一版本、分支和提交规则。
- 延续的开发范围：桌面端设备发现、文件准备、连接与投屏基础流程，以及 Windows/macOS SDK 接入。已有模块和验证结果以各仓库 README 与验证记录为准。
- 规格治理范围：两仓引入 OpenSpec，将现有设计拆为带独立规格版本的能力基线和待办变更；仅整理规格与校验工具，不因此启动尚未实现的产品功能，也不新增发布版本承诺。

本版本仍需处理或验收的工作：

- 在 macOS 编译新的 SDK 插件布局，复验权限、真实首帧、停止/恢复和资源释放。
- 修复并验收 Windows 真实本机预览首帧；本地模拟测试通过不代表真实投屏通过。
- 继续完成设备连接及远端投屏流程，验证直连及中继路径。当前本地预览不等于远端屏幕共享。
- 明确正式 SDK 分发、签名与发布验收清单，完成后才能确定稳定版发布范围。

以上是当前开发归属，不代表所有列项已完成，也不是已批准的稳定版验收结论。未来版本、发布日期以及远控、网络文件收发、激活和 Android 的具体排期尚未确定；开始相应开发前先更新版本计划。版本升级时同时修改两仓库计划、`VERSION` 和对应包版本，保留变更理由与验证记录。

## OpenSpec 开发次序（2026-09-15）

两仓全部未归档 change 统一遵循[两仓开发计划 v0.1.0](superpowers/plans/2026-09-15-cross-repository-development.md)：

1. 第一轮指定桌面真实预览现状/根因收敛；连接身份、配对、信令契约及资格依赖决定可并行准备。
2. 随后完成桌面与本地可信连接，再接辅助连接和直连/中继，之后验收桌面远端投屏。
3. SDK 格式设计可前置，正式交付按实际声明能力的验证结果推进。续期作为独立维护优先项，媒体实验按桌面与 Android 所需子集穿插。
4. 激活资格、网络文件、远控、官方 Android 和第三方 Android SDK 保持 unassigned；本计划指定依赖顺序，产品实现前仍需明确版本归属。

**上线阻塞必须显式保留：** 官方登记/转发/凭据服务需要资格验证链路；激活尚未排期，因此工程联调不等于可正式上线。先完成资格基础，再联测已激活设备的离线核心操作，避免激活与连接互相等待全部完成。

本轮授权为规格同步和计划制定，未启动上述产品实现、采集或云维护；开发计划阶段不是发布日期，124 项原实施任务保持未完成。计划正文在两仓同路径同步，公开版本不依赖私有文件或生产环境信息。
